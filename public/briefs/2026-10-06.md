DHH 对 Rust 的看法从根本上是正确的。作为背景，Vercel 已经进行了一段时间的 Rust 化（严格来说是“癌变”🦀）。

我们迁移的首批项目之一是 Turborepo，从 Go 迁移到 Rust¹。迁移已经完成，但其投资回报率在内部却引发了相当大的争议。

虽然我们认为 Rust 在底层操作系统访问方面更胜一筹（这对像 Turbo 这样的构建系统至关重要），但人力迁移成本却非常高昂。

Go 速度很快，设计精美，易于迭代。我们对迁移感到非常纠结，因为编写代码的是*人*，*即使我们知道 Rust 是更好的选择*。

现在情况发生了变化。“对人最有利”的不再一定是“对业务最有利”。

顺便一提，Rust 也不太可能是最终的万能工具链。我确信未来一片光明，因为 Rust 本身的设计早于代理程序如潮水般涌来之时。

¹ https://vercel.com/blog/how-turborepo-is-porting-from-go-to-rust

<details><summary>英文原文</summary>

**DHH is fundamentally right about Rust.**

DHH is fundamentally right about Rust. For context, Vercel has been undergoing a Rust-ification (carcinization, technically 🦀) for a while.

One of the first projects we migrated was Turborepo, from Go to Rust¹. The migration completed, but the RoI was actually quite controversial internally.

While Rust was in our eyes better for low-level OS access, something crucial for a build system like Turbo, the human migration costs were very sustantive.

Go is very fast. It's beautifully designed. It's easy to iterate on. We were very conflicted about the migration, because it was *humans* writing the code, *even if we knew Rust was a better choice*.

The calculus has now changed. What's "best for humans" is no longer necessarily "best for business". 

FWIW, it's also quite unlikely that Rust is the end-all-be-all toolchain. I'm quite certain there's greener pasture ahead, because Rust itself was designed before the 'supersonic tsunami' of agents hit.
