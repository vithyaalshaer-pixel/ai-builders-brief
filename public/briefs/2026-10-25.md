智能体可以在云端玩“碟仙”游戏。

这类针对共享主机虚拟机的计时攻击至少从 2015 年¹ 就已为人所知，但一直没有完整的解决方案。

全球网络基础设施的运行依赖于这样一种假设：“没错，这种攻击理论上是可能的，但谁会有足够的创造力和胆量去这么做呢！” 智能体应运而生。

我会将 OpenAI 发现的这种攻击描述为“嘈杂邻居”攻击。如果两个智能体运行在同一台机器上，其中一个可以通过 CPU 缓存发出足够的“噪音”，让另一个智能体通过计时自身的计算和缓存访问来检测到它。

唯一“完整”的解决方案是让每个智能体运行在独立的专用硬件上，但这显然会带来巨大的经济成本。

对于 Vercel Sandbox，我们部署了所有可行的缓解措施来应对这类攻击，并辅以全天候监控和红队演练（类似于 OpenAI 的做法）。

**Agents can play "Ouija" in the cloud.**

Agents can play "Ouija" in the cloud.

This class of timing attacks on shared-host VMs has been known since at least 2015¹. With no full solution.

The world’s cyber infrastructure runs on “yes, that attack is theoretically possible, but who would have the ingenuity & gall to go that far!” Enter, agents.

I'd describe this particular OpenAI find as a 'noisy neighbor' attack. If two agents are on the same machine, one can make enough noise (through the CPU caches!) that the other one can detect it by timing its own computation and cache accesses.

The only "complete" solution would be for each agent to run on its own dedicated hardware, which obviously has significant economic consequences.

For Vercel Sandbox, we've deployed every practical mitigation possible to this class of attack, complementing it with always-on monitoring and red-teaming (similar to where OpenAI arrived).
